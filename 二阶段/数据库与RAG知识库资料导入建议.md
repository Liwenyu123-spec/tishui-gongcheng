# 二阶段：数据库与 RAG 知识库资料导入建议

## 1. 判断原则

- **业务数据库**：保存需要按站点、时间、状态、编号进行查询、统计、告警和审计的数据。
- **RAG 知识库**：保存需要通过语义检索、原文引用和版本管理来回答的问题。
- **双重入库**：既有结构化字段，又需要全文检索和上下文解释的资料。

本文依据：《李文聿提水工程供水调度平台项目规划书》《提水工程供水调度平台项目需求》。

## 2. 应导入业务数据库的资料

### 2.1 工程基础与拓扑

- 娘子关取水点、集泉一站、一至四泵站
- 渠道、调蓄设施、平定侧供水泵站和下游供水片区
- 站点编码、顺序、输水方向、启用状态
- 泵站与供水片区映射
- 渠道输水能力、输水时延和有效时间

建议对象：`stations`、`links`、`supply_areas`、`station_area_map`。

### 2.2 设备台账与测点字典

- 水泵、机组、阀门、闸门和仪表
- 设备编号、型号、所属站点、启用状态
- 泵组数量、备用泵配置、流量压力水位电流能耗测点
- 测点编码、单位、采样周期、来源、质量码、异常码
- 设备运行边界、上下限和告警阈值

建议对象：`devices`、`measurement_points`、`metric_definitions`、`thresholds`。

### 2.3 实时及历史运行数据

- 进出水压力、流量、水池及渠道水位
- 泵组运行状态、电流、功率、能耗
- 平定侧供水量、压力、库存水位
- 站点心跳和在线状态
- 数据来源、采集时间、单位、质量状态
- 缺失、过期和异常标记

建议对象：`telemetry_readings`、`station_heartbeats`、`data_quality_records`。

> 时序数据不应直接放入 RAG，RAG 不能代替数据库进行数值计算。

### 2.4 供水计划与需求

- 日计划、周计划、临时计划及其版本、审批状态、生效时间
- 各片区计划供水量、实际供水量
- 需求观测、需求预测和调蓄余量
- 计划检修造成的能力变化
- 经授权接入的天气、节假日等外部影响

建议对象：`supply_plans`、`demand_observations`、`external_factors`、`reservoir_levels`。

### 2.5 告警、事件、通知和升级

- 设备告警、站点人工上报事件
- 事件类型、严重等级、发生时间、来源、上报人
- 待确认、处理中、已解决、误报关闭等状态
- 事件指纹、重复事件合并次数
- 值班联系人、备用联系人、通知渠道
- 发送、送达、失败、重试和升级记录

建议对象：`alarms`、`incidents`、`station_contacts`、`escalation_rules`、`notifications`、`notification_deliveries`。

### 2.6 巡检、维修和设备健康

- 巡检记录、维修工单
- 故障现象、原因、措施、备件
- 维修时间、责任人、复测结果
- 设备健康状态和未闭环问题

建议对象：`inspections`、`work_orders`、`maintenance_records`、`equipment_health`。

### 2.7 方案、审批、报告和审计

- 备选调度方案及供水量、时延、能耗、负荷、风险
- 建议、复核、批准、驳回和执行反馈
- 日报、周报、交接班摘要元数据
- 用户查询、Agent 工具调用、审计日志
- 数据版本、知识版本和引用关系

建议对象：`scheme_comparisons`、`dispatch_reviews`、`shift_handovers`、`reports`、`audit_logs`、`agent_runs`。

## 3. 应导入 RAG 知识库的文档

### 3.1 一级优先级：上线前必须准备

**运行规程与调度制度**

- 各泵站运行规程、启停泵操作规程
- 调度管理制度、供水调度规则
- 值班、交接班、操作票和工作票制度
- 异常工况处置、超压、低压、断流、停电处理规定

**应急预案**

- 泵站故障、供水中断、渠道异常、水位异常预案
- 停电、通信中断、极端天气预案
- 重大设备事故处置流程
- 通知失败和人工电话兜底流程

**设备说明书与技术手册**

- 水泵、电机、变频器说明书
- 阀门、闸门、仪表手册
- PLC、DCS、SCADA 只读接口说明
- 水泵性能曲线、运行边界
- 联锁、保护逻辑和备件手册

**工程拓扑和设备档案文档**

- 正式工程拓扑图、工艺流程图、管渠连接图
- 站点平面图或 GIS 图
- 设备台账、泵组配置表
- 站点与片区映射表
- 测点清单和数据字典

拓扑、编码、关系和参数进入数据库；图纸说明、字段解释和版本说明进入 RAG。

### 3.2 二级优先级：异常诊断与历史问答

- 巡检报告、维修报告、故障处理单
- 设备更换记录、事故报告、异常事件复盘
- 典型故障案例、设备健康评估报告
- 历史调度日志、运行日报、周报、交接班记录
- 历史告警处置记录
- 典型高峰期、低谷期运行方案

时间序列和统计字段进入数据库；经过审核的文字记录进入 RAG。

### 3.3 三级优先级：供需和通知管理

- 供水片区边界、供水指标和计划用水制度
- 需求预测口径、调蓄设施管理规定
- 高峰、节假日和特殊时期供水规则
- 事件分级、告警分级、通知对象和升级规则
- 联系人维护、通知脱敏、留存审计和人工接管流程

联系人、渠道、超时时间等配置进入数据库；制度和流程说明进入 RAG。

## 4. 建议双重入库的资料

| 资料 | 数据库保存 | RAG 保存 |
|---|---|---|
| 工程拓扑 | 站点、连接、方向、时延、容量 | 拓扑图说明、变更说明 |
| 设备台账 | 编号、型号、站点、状态 | 设备档案、说明书和性能解释 |
| 测点字典 | 编码、单位、采样周期、质量码 | 指标定义、计算口径 |
| 维修记录 | 时间、设备、状态、责任人、结果 | 维修报告、故障原因和经验 |
| 历史事件 | 等级、时间、状态、关联告警 | 事件经过、复盘结论和依据 |
| 供水计划 | 计划量、片区、版本、状态 | 编制规则、调整原则和审批制度 |
| 交接班记录 | 时间、班次、未闭环事项 | 交接班全文和处置背景 |
| 应急预案 | 编号、版本、生效状态 | 预案正文和操作步骤 |

## 5. 不建议进入正式 RAG 检索集合的内容

- 未确认的拓扑草图
- 过期或废止规程
- 未审核的个人经验
- 没有来源的聊天记录
- 测试用 Mock 数据、临时截图和重复文件
- 没有时间、站点、责任人的异常描述
- 把模型推测写成结论的分析报告
- 包含不必要个人敏感信息的联系人资料
- PLC 控制命令或控制凭据

这些内容如需保留，应放入待审核区或归档区。

## 6. 首批导入顺序

### 第一批：最小可用知识底座

1. 正式工程拓扑和站点清单
2. 设备台账和测点字典
3. 各泵站运行规程
4. 调度制度和操作票
5. 应急预案
6. 水泵及关键设备说明书
7. 现行告警分级和联锁规则
8. 已确认的历史异常案例

### 第二批：增强分析能力

1. 巡检记录
2. 维修工单和维修报告
3. 历史告警及处置记录
4. 交接班记录
5. 历史调度日志
6. 供水计划和片区需求资料
7. 渠道输水和调蓄资料

### 第三批：完善事件通知闭环

1. 站点联系人配置
2. 备用联系人和升级规则
3. 通知渠道规范
4. 事件分级和确认时限
5. 通知失败和人工兜底流程

## 7. 项目自身文档的处理建议

项目规划书、需求文档、README、前端说明和开发日志属于项目设计与开发资料，不属于现场运行知识。

建议：

- 不与正式水务规程混入同一个 RAG 集合；
- 如有需要，单独建立“项目文档库”；
- 正式水务 RAG 只保留经过审核、版本有效、适用站点明确的资料。

## 8. 结论

- **数据库必备**：拓扑、站点、设备、测点、运行数据、计划、需求、告警、事件、通知、维修、审批和审计记录。
- **RAG 必备**：运行规程、调度制度、操作票、应急预案、设备手册、性能曲线、联锁规则、维修报告和已确认的历史事件复盘。
- **双重入库**：拓扑、设备台账、测点字典、维修记录、历史事件和供水计划。
- **首期重点**：先完成正式拓扑、设备测点、现行规程、应急预案和关键设备资料的整理与审核。
